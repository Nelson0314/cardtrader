# CardTrader 球員卡交易管理系統 — 規格書

網站：https://nelson0314.github.io/cardtrader/

## 1. 目的與使用情境

本系統供個人球員卡賣家記錄進貨、出貨、雜項支出，並統計庫存、成本與損益。使用情境為單一使用者在自己的電腦上管理帳本，並可產生商品目錄圖片提供給買家。

主要需求：

1. 每項商品記錄名稱、圖片、庫存，以及完整的進出貨歷史。
2. 進貨時記錄付款方式；信用卡的手續費與回饋在統計時獨立列出。
3. 依任意日期區間或單一商品查詢收支、淨利與淨利率。
4. 歷史資料不可遺失，任何寫入都必須可以回復。

## 2. 功能規格

| 頁面 | 功能 | 互動行為 |
|---|---|---|
| 📦 商品管理 | 統計卡片：商品種類、總庫存、總進貨成本（含手續費）、總銷售收入。商品卡片：庫存、已售出、平均成本、均售出價、平均報酬率 | 有庫存的商品排在前面；庫存 ≤ 3 以橘色標示，0 以紅色標示。每張卡片可「編輯／進貨／出貨／查看明細」 |
| ➕ 新增商品 | 名稱、圖片、進貨總金額、付款方式、數量、日期 | 圖片可點選或拖曳上傳，自動縮至 400 px 並轉成 JPEG；新增後同時建立第一筆進貨紀錄 |
| 進貨／出貨視窗 | 數量、金額、日期；進貨另有付款方式 | 出貨數量超過庫存時拒絕；進貨的付款方式預設為設定頁指定的預設方式 |
| 🧾 記錄雜支 | 說明、分類（運費、折扣、包裝費、關稅、平台費、其他）、金額、日期 | 雜支計入淨利，不綁定商品 |
| ✏️ 編輯商品 | 修改名稱、圖片、庫存；刪除商品 | 改名時同步更新相關交易的商品名稱；刪除前需要確認 |
| 📊 歷史數據 | 日期區間篩選、單一商品篩選、統計卡片、每月收支長條圖、交易明細表 | 明細表列出付款方式、原始金額、手續費、回饋、成本／收入；可刪除單筆紀錄，刪除時回補庫存 |

每個頁面都有網址錨點（例如 `index.html#history`），可以直接開啟指定頁面。手機寬度下側欄收合為漢堡選單，表格可橫向捲動。

## 3. 計算規則

每筆進貨只儲存原始金額與當下付款方式的費率（百分比）。手續費與回饋在統計時計算，所以修改設定不會改變過去的紀錄。

設原始金額為 *A*、手續費率為 *f*、回饋率為 *r*：

- 淨成本 = ⌈ *A* × (1 + *f* − *r*) ⌉（無條件進位）
- 回饋 = ⌊ *A* × *r* ⌋（無條件捨去）
- 手續費 = 淨成本 − *A* + 回饋
- 進貨成本（含手續費）= *A* + 手續費

為了避免 `1 + 0.015 − 0.025` 這類浮點誤差，費率先換成萬分位整數再運算。

統計指標：

- 淨利 = 銷售收入 + 回饋 − 進貨成本（含手續費）− 雜支
- 淨利率 = 淨利 ÷ 銷售收入
- 平均成本 = 該商品所有進貨的淨成本總和 ÷ 進貨數量（四捨五入）
- 平均報酬率 = (均售出價 − 平均成本) ÷ 平均成本

v1 在進貨當下直接把金額 × 0.99 存成成本，相當於信用卡手續費 1.5%、回饋 2.5%。v2 把舊紀錄回溯為「信用卡 1.5%／2.5%」，並逐筆確認新公式算出的淨成本等於舊紀錄的成本，因此淨利、淨利率、平均成本與報酬率都和 v1 相同。

## 4. 資料模型

```jsonc
{
  "version": "2.0",
  "lastUpdated": "ISO 時間，用於偵測寫入衝突",
  "settings": {
    "paymentMethods": [{ "id": "card", "name": "信用卡", "feeRate": 1.5, "rebateRate": 2.5 }],
    "defaultPaymentMethod": "card"
  },
  "products": [{ "id": "…", "name": "…", "imageDataUrl": "data:image/jpeg;base64,…", "stock": 4, "costPerUnit": 1000, "createdAt": "…" }],
  "transactions": [
    { "id": "…", "type": "purchase", "productId": "…", "productName": "…", "quantity": 2, "unitPrice": 1124, "totalCost": 1124,
      "paymentMethod": "信用卡", "feeRate": 1.5, "rebateRate": 2.5, "date": "…" },
    { "type": "sale", "quantity": 1, "unitPrice": 750, "totalCost": 750, "…": "…" },
    { "type": "expense", "productId": null, "expenseCategory": "運費", "totalCost": 120, "…": "…" }
  ]
}
```

進貨的 `totalCost` 是整筆進貨的總金額；出貨的 `totalCost` = 單價 × 數量。

## 5. 執行模式與架構

整個前端是單一檔案 `index.html`（HTML、CSS、JavaScript 都寫在裡面；外部只載入 html2canvas 和 Google Fonts）。程式依網址自動判斷儲存方式：

| 模式 | 判斷條件 | 資料來源 | 用途 |
|---|---|---|---|
| 本機模式 | `localhost:3000` | `server.py` 讀寫 `data.json` | 日常記帳 |
| 網頁模式 | 其他網址（GitHub Pages） | 瀏覽器 IndexedDB；首次開啟時載入網站上的 `data.json` 快照 | 展示與操作，變更只保存在訪客自己的瀏覽器 |

本機啟動方式：執行 `啟動球員卡系統.vbs`。它以隱藏視窗啟動 `python server.py` 並開啟瀏覽器；伺服器 3 分鐘沒收到網頁的 ping 就會自動結束。

## 6. 資料保護

| 風險 | 處理方式 |
|---|---|
| 寫入途中當機導致檔案損毀 | 先寫入暫存檔並 `fsync`，再用 `os.replace` 取代 |
| 誤操作或程式錯誤覆寫資料 | 每次寫入前把現有的 `data.json` 複製到 `backups/`，保留最近 50 份 |
| 兩個分頁同時開啟，舊分頁覆蓋新資料 | 寫入時附上載入當下的 `lastUpdated`；伺服器比對不一致就回應 409，頁面停止寫入並提示重新整理 |
| 伺服器沒啟動時，頁面用不完整的資料覆寫 | 讀取失敗時頁面進入唯讀狀態，並在頁首顯示錯誤訊息，不改用瀏覽器內的舊資料 |
| 送出空帳本或格式錯誤的資料 | 伺服器拒絕非 JSON、缺少陣列，以及把非空帳本清空的請求 |
| 背景分頁計時器被節流，伺服器提前關閉 | 逾時從 8 秒放寬為 3 分鐘；切回分頁時立即檢查伺服器狀態 |
| 其他網站或區網裝置存取本機 API | 只綁定 127.0.0.1、檢查 Host 標頭、不送出 CORS 標頭 |
| 商品名稱含有 HTML 字元 | 插入頁面前一律跳脫 |

## 8. 驗證

- 數值一致性：以 v2 頁面實際顯示的數字，對照 v1 資料以舊公式算出的結果。84 張商品卡的平均成本與報酬率、淨利（$52,034）、淨利率（7.7%）、540 筆明細全部相符。
- 端對端測試（Playwright，29 項全數通過）：
  - 設定儲存、新增付款方式並設為預設。
  - 新增商品與進貨（手續費 $15、回饋 $25、成本 $1,015 的範例）、出貨、篩選後的統計數字。
  - 刪除商品時連帶刪除其交易。
  - 舊分頁寫入被拒絕，且資料未被修改。
  - 伺服器拒絕空帳本、格式錯誤、外部 Host 與過期版本。
  - 網頁模式：載入快照、重新整理後資料仍在、重設、匯出。
  - 手機寬度（390 px）各頁沒有橫向捲動。
